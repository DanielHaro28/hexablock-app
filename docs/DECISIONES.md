Se integran en orden con *squash*; después de integrar uno, la rama del siguiente **integra `main` con un merge** (`git merge origin/main`) y su base se cambia a `main` a mano (`gh pr edit --base main`), porque las ramas no se borran. **Precisión (24-11):** no se rebasa, porque subir una rama rebasada exige *force push* y SEC-AGT-02 lo prohíbe (el *hook* de git lo bloquea); el *squash* final oculta el commit del merge. Así "un Issue por PR" significa que un PR nunca mezcla dos Issues, no que un Issue tenga un solo PR. Cada PR pasa por su propia revisión de otra área (D-62) y por el CI. Motivo: el PR #123 quedó con unas 3.000 líneas en más de 60 archivos, demasiado para revisarlo con cuidado.
